2  Bash básico

2.1 Introducción a Unix/Bash

2.1.1 Cómo usar este material

  • Espacio de trabajo seguro: Crea y trabaja siempre dentro de un directorio de práctica dedicado.
  • Ejecución consciente: Copia/pega comandos con atención. Lee antes de ejecutar.
  • Metodología activa: En cada ejercicio, escribe el comando y una breve explicación de lo que esperas ver (predicción → ejecución → verificación).
  • Autocompletado: Usa la tecla TAB para completar rutas y nombres de archivos.
  • Ayuda: Usa man comando para consultar el manual (presiona q para salir).

2.2 Objetivos de aprendizaje

Al finalizar esta guía, podrás:

  • Navegar eficientemente por el sistema de archivos (pwd, ls, cd).
  • Gestionar archivos y directorios (mkdir, cp, mv, rm).
  • Inspeccionar y explorar archivos de texto (cat, less, head, tail, wc).
  • Buscar patrones con grep y expresiones regulares básicas.
  • Encadenar comandos mediante tuberías (|) y redirecciones (>, >>).
  • Utilizar comodines (wildcards) de forma efectiva.
  • Comprimir y descomprimir archivos y directorios (tar, gzip).
  • Realizar transformaciones básicas de texto con sed y awk.

2.3 Convenciones tipográficas

  • $ indica un comando que se debe escribir en la terminal (no se incluye el prompt real).
  • archivo.txt, directorio/ son ejemplos; reemplázalos por tus rutas reales.
  • Los bloques de código muestran comandos y su salida esperada.
  • TAB representa la tecla de autocompletado.
WarningSeguridad básica (¡Muy importante!)
  • Cuidado con rm -r: Evita usarlo hasta entender perfectamente qué elimina.
  • Verifica antes de borrar: Usa pwd para confirmar tu ubicación y ls para listar el contenido.
  • Espacio de práctica: Realiza los ejercicios de eliminación solo en tu directorio de práctica.
  • Copia de seguridad: Considera hacer copias de archivos importantes antes de modificarlos o eliminarlos.

3 Navegación y estructura básica

3.1 Comandos esenciales

Comando Descripción Ejemplo
pwd Muestra el directorio de trabajo actual (print working directory). $ pwd
ls Lista archivos y directorios. $ ls
ls -a Lista todos los archivos, incluidos los ocultos (que empiezan por .). $ ls -a
ls -l Lista con formato largo (detalles de permisos, tamaño, etc.). $ ls -l
ls -la Combina -l y -a. $ ls -la
cd Cambia de directorio (change directory). $ cd /ruta/destino
cd ~ Te lleva a tu directorio personal ($HOME). $ cd ~
cd .. Sube un nivel (al directorio padre). $ cd ..
mkdir Crea un nuevo directorio (make directory). $ mkdir nuevo_dir

  1. Abre una terminal.
  2. Ejecuta pwd. ¿Qué muestra? ¿Es el directorio que esperabas?
  3. Ejecuta ls -la. ¿Qué tipos de archivos y directorios ves? ¿Reconoces algunos?

Ejercicio 2.1 (resuelto): Navegación relativa vs. absoluta

4 Gestión de archivos y directorios

4.1 Comandos de gestión

Comando Descripción Ejemplo
touch Crea un archivo vacío o actualiza su marca de tiempo. $ touch archivo.txt
cp Copia archivos o directorios. $ cp origen destino
mv Mueve o renombra archivos/directorios. $ mv viejo nuevo
rm Elimina archivos (¡Cuidado! No va a la papelera). $ rm archivo.txt
rmdir Elimina un directorio vacío. $ rmdir dir_vacio
rm -r Elimina un directorio y todo su contenido (¡Extrema precaución!). $ rm -r directorio/
TipTruco: Confirmación y verbose

  • Usa la opción -i (interactive) con cp, mv o rm para que el sistema pregunte antes de sobrescribir o eliminar.

    cp -i archivo1 archivo2
rm -i archivo.txt

  • Usa -v (verbose) para que los comandos muestren qué están haciendo.

    cp -v origen destino

4.2 Visualización y exploración de archivos

4.2.1 Comandos de inspección

Comando Descripción Opciones comunes
cat Concatena y muestra el contenido completo de uno o varios archivos. -n (numera líneas)
less Muestra el contenido de un archivo página a página (usa flechas, Espacio para avanzar, q para salir).

4.3 Búsqueda de patrones con grep

grep es una herramienta poderosa para buscar líneas que coincidan con un patrón (texto simple o expresión regular) en uno o varios archivos.

4.3.1 Opciones comunes de grep

Opción Descripción
-i Búsqueda insensible a mayúsculas/minúsculas.
-w Coincide solo con palabras completas.
-c Cuenta el número de líneas que coinciden.
-n Muestra el número de línea de cada coincidencia.
-v Invierte la búsqueda (muestra líneas que NO coinciden).
-l Solo lista los nombres de los archivos que contienen coincidencias.
-A N Muestra N líneas después de la coincidencia (After).
-B N Muestra N líneas antes de la coincidencia (Before).
-C N Muestra N líneas antes y después de la coincidencia (Context).

4.3.2 Archivo de ejemplo

Crea un archivo sistemas.txt con el siguiente contenido para los ejercicios:

$ cat > sistemas.txt << 'EOF'
Unix es un sistema operativo.
Los sistemas UNIX tienen interfaz gráfica.
Unix fue desarrollado en los años 60.
UNIX es poderoso.
Este texto no tiene la palabra.
Linux es otro sistema operativo.
El sistema operativo macOS está basado en UNIX.
Hay sistemas operativos de todo tipo.
EOF

4.3.3 Ejercicios con grep

Ejercicio 6.1: Búsqueda básica

Busca todas las líneas que contengan la palabra “Unix”, ignorando mayúsculas/minúsculas.

grep -i "unix" sistemas.txt

Ejercicio 6.2: Conteo

Cuenta cuántas líneas contienen “sistema”.

grep -c "sistema" sistemas.txt

Ejercicio 6.3: Números de línea

Muestra las líneas que contienen “operativo” junto con su número de línea.

grep -n "operativo" sistemas.txt

Ejercicio 6.4: Invertir búsqueda

Muestra las líneas que NO contienen la palabra “Unix”.

grep -v -i "unix" sistemas.txt

Ejercicio 6.5: Palabra completa

Busca la palabra “sistema” como palabra completa (no “sistemas”).

grep -w "sistema" sistemas.txt

4.3.4 Expresiones regulares básicas con grep

grep acepta expresiones regulares (regex) para búsquedas más complejas.

Patrón Significado Ejemplo (coincide con)
^ Inicio de línea. ^Unix (líneas que comienzan con “Unix”)
$ Fin de línea. .$ (líneas que terminan con un punto)
. Cualquier carácter (excepto salto de línea). s.ste.a (“sistema”, “sisteia”, etc.)
* Cero o más repeticiones del carácter anterior. sist*ema (“sistema”, “sisttema”, etc.)
[ ] Conjunto de caracteres. [Uu]nix (“Unix” o “unix”)
[^ ] Negación del conjunto. [^0-9] (cualquier carácter que no sea un dígito)

Ejercicio 6.6: Regex - Inicio de línea

Busca líneas que comiencen con “Unix” (sensible a mayúsculas).

grep "^Unix" sistemas.txt

Ejercicio 6.7: Regex - Fin de línea

Busca líneas que terminen con un punto.

grep ".$" sistemas.txt

Ejercicio 6.8: Regex - Dígitos

Busca líneas que contengan al menos un dígito.

grep "[0-9]" sistemas.txt

4.3.5 Más patrones de expresiones regulares (BRE vs. ERE)

grep usa expresiones regulares básicas (BRE) por defecto. Con la opción -E (o el comando egrep) se activan las expresiones regulares extendidas (ERE), que permiten usar cuantificadores y agrupaciones sin tener que escaparlos con \.

Patrón Significado Requiere -E Ejemplo
+ Una o más repeticiones del carácter/grupo anterior. Sí (en BRE: \+) grep -E "o+" sistemas.txt
? Cero o una repetición (opcional). Sí (en BRE: \?) grep -E "colou?r" archivo
{n,m} Entre n y m repeticiones. Sí (en BRE: \{n,m\}) grep -E "[0-9]{2,4}" archivo
( ) Agrupa una subexpresión. Sí (en BRE: \( \)) grep -E "(Uni|Lin)x" archivo
\| Alternancia (OR). Sí grep -E "Unix\|Linux" archivo
\b Límite de palabra (extensión GNU). No grep "\bUnix\b" archivo
TipBRE vs. ERE en la práctica

Si vas a usar +, ?, {}, () o |, es más simple y legible agregar -E en lugar de escapar cada símbolo con \. Muchos practicantes usan grep -E (o directamente egrep, aunque está en desuso) como su modo por defecto.

Ejercicio 6.12 (resuelto): Alternancia con -E

Busca líneas que contengan “Unix” o “Linux” (respetando mayúsculas) usando alternancia.

grep -E "Unix|Linux" sistemas.txt

Ejercicio 6.13 (resuelto): Cuantificador {n,m}

Del archivo libro.txt (que crearás en el Ejercicio A más abajo), busca palabras de entre 6 y 8 letras exactamente.

grep -oE "\b[a-zA-ZáéíóúÁÉÍÓÚñÑ]{6,8}\b" libro.txt

Ejercicio 6.14 (propuesto): Usando sistemas.txt, busca líneas donde aparezca la palabra “sistema” seguida, en algún punto posterior de la misma línea, de la palabra “operativo” (no necesariamente contiguas).

NotePista

.* entre dos patrones significa “cualquier cosa en medio, incluyendo nada”.

Ejercicio 6.15 (propuesto, sin solución): Escribe un patrón con grep -E que capture líneas de sistemas.txt que empiecen con “Unix” o con “UNIX” o con “Linux”, usando un solo grupo de alternancia anclado al inicio de línea (^(...)). Verifica tu resultado comparándolo con el de grep -i "^unix\|^linux".

Objetivo: Generar un fragmento del inicio de un libro y usar expresiones regulares con grep para buscar patrones.

Crea un archivo llamado libro.txt con el siguiente contenido:

Capítulo 1

Los personajes principales eran: Ana, Juan, María y Pedro. Sus edades: 25, 30, 22 y 35 años respectivamente.

5 Redirecciones y tuberías (Pipes)

Conceptos clave

Salida estándar (stdout): Donde los comandos envían sus resultados por defecto (normalmente la pantalla).

Redirección: Capturar la salida de un comando y enviarla a un archivo.

>  redirige la salida a un archivo (sobrescribe) 
>> redirige la salida añadiendo al archivo 
|  envía la salida de un comando como entrada a otro

Ejemplos

# Guardar la lista de archivos en un archivo
ls -la > listado_completo.txt
# Añadir la fecha al final de un archivo
$ date >> listado_completo.txt
# Filtrar la lista para mostrar solo archivos .txt
$ ls -la | grep ".txt"
# Contar cuántos archivos .txt hay
$ ls *.txt | wc -l

9 Descarga de archivos desde la terminal con wget y curl

9.1 Introducción a wget y curl

En entornos Unix/Linux, wget y curl son dos herramientas fundamentales para transferir datos desde la línea de comandos. Aunque comparten funcionalidades, tienen enfoques y características diferentes:

Característica wget curl
Enfoque principal Descarga recursiva de sitios web y archivos Transferencia de datos con múltiples protocolos
Protocolos HTTP, HTTPS, FTP HTTP, HTTPS, FTP, FTPS, SCP, SFTP, TFTP, LDAP, y más
Recursividad Sí (descarga enlaces internos) No (por defecto)
Seguimiento de redirecciones Sí (automático) Sí (con opción -L)
Reanudar descargas Sí (-c) Sí (-C -)
Interacción con APIs Limitada Excelente (envía datos, headers personalizados)
Scripting Bueno para descargas automáticas Mejor para APIs y transferencias complejas

9.2 wget: El descargador web

Sintaxis básica

wget [opciones] [URL]

Ejemplos comunes

  1. Descargar un archivo simple:
wget https://ejemplo.com/archivo.zip
  1. Descargar con nombre personalizado:
wget -O mi_archivo.zip https://ejemplo.com/archivo.zip
  1. Descargar en segundo plano:
wget -b https://ejemplo.com/archivo_grande.iso
  1. Reanudar una descarga interrumpida:
wget -c https://ejemplo.com/archivo_interrumpido.zip
  1. Descargar recursivamente un sitio web:
wget -r -l 2 --no-parent https://ejemplo.com/seccion/
  • -r: recursivo
  • -l 2: profundidad de 2 niveles
  • --no-parent: no subir al directorio padre
  1. Descargar todos los archivos de un tipo específico, en este caso todos los pdfs:
wget -r -A "*.pdf" https://ejemplo.com/documentos/
  1. Descargar desde una lista de URLs:
wget -i lista_urls.txt

Por ejemplo este es útil para descargar múltiples archivos alojados cada uno en una distinta URL

  1. Limitar velocidad de descarga:
wget --limit-rate=100k https://ejemplo.com/archivo_grande.iso

9.2.1 curl: El cliente de transferencia de datos

Sintaxis básica

curl [opciones] [URL]

Ejemplos comunes

  1. Descargar un archivo:
curl -O https://ejemplo.com/archivo.txt
  1. Descargar con nombre personalizado:
curl -o resultado.json https://api.ejemplo.com/datos
  1. Seguir redirecciones:
curl -L https://ejemplo.com/acortado
  1. Enviar una petición GET con parámetros:
curl "https://api.ejemplo.com/buscar?q=termino&pagina=1"
  1. Enviar una petición POST con datos:
curl -X POST -d "usuario=juan&clave=secreta" https://api.ejemplo.com/login
  1. Enviar datos JSON:
curl -X POST -H "Content-Type: application/json" \
  -d '{"usuario": "juan", "email": "juan@ejemplo.com"}' \
  https://api.ejemplo.com/registro
  1. Enviar archivo como datos:
curl -X POST -F "archivo=@datos.csv" https://api.ejemplo.com/subir
  1. Usar autenticación básica:
curl -u usuario:clave https://api.ejemplo.com/protegido
  1. Enviar headers personalizados:
curl -H "Authorization: Bearer token123" \
  -H "X-API-Key: abcdef" \
  https://api.ejemplo.com/datos
  1. Guardar la respuesta HTTP completa (headers + cuerpo):
curl -i https://ejemplo.com/
  1. Solo mostrar los headers de la respuesta:
curl -I https://ejemplo.com/

9.3 Consejos y mejores prácticas

Para wget:

  • Usar -q para modo silencioso en scripts.
  • -nv (no verbose) muestra solo información esencial.
  • --timeout=30 para evitar esperas infinitas.
  • --tries=3 para reintentos automáticos.
  • Verificar integridad con --checksum cuando esté disponible.

Para curl:

  • Usar -s (silent) y -S (show error) en scripts: curl -sS.
  • -f para fallar en respuestas HTTP de error.
  • -w para formato personalizado de salida.
  • Guardar cookies con -c y reutilizarlas con -b.
  • Usar --retry para reintentos automáticos.

Seguridad:

  • Verificar certificados SSL (activo por defecto en ambas herramientas).
  • No enviar credenciales en la línea de comandos; usar variables de entorno.
  • Validar las URLs antes de descargar.
  • Limitar los permisos de los archivos descargados.

$(find . -name "*.csv" -o -name "*.json" | sed 's/^/- /')

## Estadísticas
- Total archivos: $(find . -type f \( -name "*.csv" -o -name "*.json" \) | wc -l)
- Tamaño total: $(du -sh . | cut -f1)
EOF

echo "=== Proceso completado ===" | tee -a "$LOG"
echo "Reporte generado: $DIR_TRABAJO/reporte_${FECHA}.md" | tee -a "$LOG"

9.5 Resumen

Usa wget cuando necesites descargar archivos individuales, sitios web completos, o realizar descargas recursivas. Usa curl cuando trabajes con APIs REST, necesites enviar datos complejos, o requieras mayor control sobre las peticiones HTTP. Ambas herramientas son complementarias y dominarlas te permitirá automatizar tareas de descarga y procesamiento de datos eficientemente.

10 Proyecto final: Script de backup automatizado

Objetivo: Crear un script de Bash que realice un backup de todos los archivos modificados en los últimos 7 días dentro de un directorio específico.

Requisitos del script (backup_reciente.sh):

  1. Debe recibir el directorio a respaldar como primer argumento.
  2. Crear un archivo comprimido (.tar.gz) con los archivos modificados en los últimos 7 días.
  3. El nombre del archivo de backup debe incluir la fecha (formato: backup_YYYY-MM-DD.tar.gz).
  4. Mover el archivo de backup a un directorio central de backups (por ejemplo, ~/backups/).
  5. Registrar la operación (fecha, directorio respaldado, nombre del archivo) en un archivo de log (~/backups/backup.log).

Esqueleto del script:

#!/bin/bash

# Verificar que se proporcionó un directorio
if [ $# -ne 1 ]; then
    echo "Uso: $0 <directorio_a_respaldar>"
    exit 1
fi

DIR_ORIGEN="$1"
DIR_BACKUP="$HOME/backups"
LOG="$DIR_BACKUP/backup.log"
FECHA=$(date +%Y-%m-%d)
ARCHIVO_BACKUP="$DIR_BACKUP/backup_$FECHA.tar.gz"

# Crear directorio de backups si no existe
mkdir -p "$DIR_BACKUP"

# Crear backup (solo archivos modificados en los últimos 7 días)
find "$DIR_ORIGEN" -type f -mtime -7 -print0 | tar -czvf "$ARCHIVO_BACKUP" --null -T -

# Verificar éxito de la creación
if [ $? -eq 0 ]; then
    echo "Backup creado exitosamente: $ARCHIVO_BACKUP"
    # Registrar en el log
    echo "$(date): Backup de $DIR_ORIGEN completado -> $ARCHIVO_BACKUP" >> "$LOG"
else
    echo "Error al crear el backup." >&2
    exit 1
fi

Para ejecutar el script:

  1. Guarda el código en un archivo backup_reciente.sh.
  2. Dale permisos de ejecución: chmod +x backup_reciente.sh.
  3. Ejecútalo: ./backup_reciente.sh /ruta/del/directorio.

Extensión propuesta (sin solución): Modifica backup_reciente.sh para que, además de crear el backup, elimine automáticamente los backups de más de 30 días de antigüedad dentro de ~/backups/ (usa find con -mtime +30), y registre en el log cuántos backups antiguos fueron eliminados. Antes de usar rm dentro del script, imprime primero la lista de archivos candidatos y revísala manualmente: es la recomendación de seguridad de esta misma guía.
